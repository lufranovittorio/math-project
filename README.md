# The Math Project

A cumulative reference that develops mathematics with complete proofs, slowly
and in a strict logical order, aiming to cover all of it: foundations,
algebra, topology, analysis, geometry, number theory, discrete mathematics,
probability, differential equations, numerical analysis, optimisation, game
theory and research-level topics such as Hodge theory. It started in November
2026 from the chapters of The Hodge Project. It is organised like the
[Stacks project](https://stacks.math.columbia.edu): one LaTeX source, a strict
logical order, and a permanent tag for every result.

## Requirements

- Python 3.10 or later with plasTeX 3.1 (`pip install plasTeX`)
- A TeX distribution with `latexmk`, `pdflatex` and `dvisvgm` (MiKTeX or TeX Live)

## Commands

```
python make.py check    # labels, references (no forward references) and tags
python make.py status   # status of every chapter
python make.py tags     # give tags to new labels (also done by the builds)
python make.py pdf      # output/pdf/book.pdf
python make.py pdf-parts [part-...]  # one PDF per part in output/pdf/parts (after pdf)
python make.py html     # website in output/html
python make.py all      # pdf, pdf-parts and html
python make.py preview combinatorics ...  # pages of some chapters only (after html)
python make.py serve    # http://localhost:8000
```

The builds stop if `check` finds errors; add `--force` to build anyway.

A full build takes about 25 minutes. While writing a chapter, `python make.py
preview <slug>` rebuilds only its pages, in about 20 seconds, into
`output/html/preview/` (open http://localhost:8000/preview/<slug>.html): references to
other chapters are resolved from `book.paux`, which the last full website
build left in the root directory, and links to them lead to the pages of that
build. The part PDFs keep the numbering of the full book; references to other
parts are printed with their numbers, taken from the aux files of the full
PDF build.

## The website

Every page has a search box. A four-character tag, such as `02B9`, leads
straight to its item; anything else opens `search.html`, which looks for all
the words of the query in the statements, names and labels of the chapters,
sections and numbered items (quotes search for a phrase), with filters for
definitions, results, examples, exercises and remarks. The index,
`search-index.js`, is generated by `python make.py html` from the pages of the
website, and the search runs entirely in the browser. `tags.html` lists all
tags.

Next to the tag of a numbered statement, an icon opens `graph.html`, the
dependency graph: the statements its statement and proof refer to with
`\ref`, and those that refer to it, drawn to a chosen depth. The data,
`deps.js`, is also written by `python make.py html`.

A "Lean" badge after the tag links a result to its formalisation in Lean's
Mathlib. The links are listed in `web/mathlib.txt`, one `label declaration`
per line, and only on the website; `python make.py check` checks the labels and
`python make.py lean` downloads the list of Mathlib declarations and checks
that every name still exists. The dice button in the header opens a random
section (`sections.json`, written by `python make.py html`), and the theme
button cycles between light, dark and automatic (dark from 20:00 to 7:00).

## Publishing

The repository is https://github.com/lufranovittorio/math-project. On every
push to `main`, the workflow `.github/workflows/build.yml` installs TeX Live
and plasTeX on a GitHub runner, runs `python make.py check` and `python
make.py all`, and deploys `output/html` to GitHub Pages:
https://lufranovittorio.github.io/math-project/. So publishing is `git push`;
the run takes about 15 minutes, and its log is under the Actions tab.

Every page of the website ends with a link that opens a GitHub issue,
prefilled with the address of the page, to report an error; section pages show
the status of their chapter above the text.

## Writing

See `CLAUDE.md` for the conventions: labels, environments, proofs, diagrams
and chapter status. In short, every file in `chapters/` is one chapter, the
order in `book.tex` is the logical order, and a proof may only use what comes
before it.
